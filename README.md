# Joe + Destini Cake Vote

A tiny wedding/vow-renewal site inspired by the cream, brown/gold, botanical sandwich-board sign.

Guests scan one permanent QR code, choose **Joe** or **Destini** as the person they want cake smashed into, then see the *other person's* Venmo / Cash App / Zelle / Apple Cash details.

There is **no vote tracking and no financial integration**. Joe and Destini compare totals manually at cake cutting.

## Fastest Cloudflare Pages deployment

1. Put this folder in a GitHub repository.
2. In Cloudflare: **Workers & Pages → Create → Pages → Import existing Git repository**.
3. For the build settings use:
   - Build command: leave blank
   - Build output directory: `public`
4. Deploy once.
5. In Cloudflare create a Workers KV namespace, e.g. `cake-vote-settings`.
6. Open the Pages project → **Settings → Bindings → Add → KV namespace**.
   - Variable name: `WEDDING_CONFIG`
   - Namespace: the one you just created
7. Optional but recommended: add an environment variable/secret named `ADMIN_PASSWORD` with your preferred first passcode.
8. **Redeploy** after adding the KV binding.

Cloudflare's Pages docs require a redeploy after adding a KV binding.

## Add payment information from your phone

Open:

`https://YOUR-SITE.pages.dev/setup/`

- If you did not set `ADMIN_PASSWORD`, the first passcode is `cake2026`.
- Change the passcode on your first save.
- Enter Joe and Destini's payment handles/details.
- Add payment/deep links where available.
- You can upload Venmo/Zelle/etc. QR screenshots directly in Setup.
- Tap **Save changes**.

## Print the permanent 4 × 5 card

After the final Pages URL exists, open:

`https://YOUR-SITE.pages.dev/card/`

The card page automatically generates a QR pointing to the site's root URL. Print it at **100% / actual size**, portrait, on cardstock.

The QR does **not** point to the payment handles. It points to the site URL, so you can change handles/text later without reprinting the card.

The QR image on the print-prep page is generated by QuickChart only while preparing the physical card. Once printed, the QR is just a normal permanent URL QR and does not depend on QuickChart.

## Guest logic

- Guest chooses **Joe** → site shows **Destini's** payment options.
- Guest chooses **Destini** → site shows **Joe's** payment options.

That matches the rule: whoever raises the most gets to smash cake in the other person's face.

```bash
npm install
npm run dev
```

Wrangler will serve the static site plus Pages Functions and a local KV binding.

## Files

- `public/index.html` — guest page
- `public/app.js` — guest interaction/payment display

- `public/card/` — 4 × 5 printable QR card
- `functions/api/config.js` — tiny Cloudflare Pages Function
- `public/styles.css` — matching wedding theme

## Security notes

- `/setup/` is no-indexed but still public by URL; the passcode is the protection.
- Change the default passcode immediately if you did not set `ADMIN_PASSWORD` before deployment.
- Do not enter passwords, account numbers, routing numbers, or banking credentials. Only enter public payment handles, phone/email identifiers used for payments, payment links, and QR images.
